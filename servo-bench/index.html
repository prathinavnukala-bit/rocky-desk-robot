How this tool works, and how to reuse it

The contract. This page only ever sends one request per move: GET {base}/servo?ch=<n>&angle=<deg>. Any device that answers a plain 200 to that URL and moves the matching PCA9685 channel works with this panel, unmodified — that's the entire protocol.

Two ways to use it. Point Device at a board's IP (e.g. 192.168.1.50) to drive it from here directly — works when this file is opened locally or from a plain http:// page. Opened from an https:// page (like a claude.ai link), the browser's mixed-content rule blocks calls to a plain http:// device, so nothing will move — use the saved local copy of this file for that, or the option below.

Or embed it. The button below copies this whole page as a C++ raw-string ready to paste into a PROGMEM constant and serve directly from the device's own web server — same-origin, so leave Device blank and it just works, no CORS or mixed-content issue at all. That's the pattern this panel was pulled out of.

const char SERVO_PAGE[] PROGMEM = R"HTMLPAGE(
...
)HTMLPAGE";

server.on("/", HTTP_GET, [](){ server.send(200, "text/html", SERVO_PAGE); });
server.on("/servo", HTTP_GET, [](){
  int ch = server.arg("ch").toInt();
  int angle = server.arg("angle").toInt();
  pwm.setServoAngle(ch, angle);   // your own PCA9685 write helper
  server.send(200, "text/plain", "OK");
});

Channel names and their min/max limits are saved in this browser automatically, per device address, so re-opening the page later remembers what you found safe last time.
